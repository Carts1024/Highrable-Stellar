# Convex Overview

Highrable's application backend is the `packages/backend` workspace package. Its Convex source lives in `packages/backend/convex`; the generated API/data-model files are under `packages/backend/convex/_generated` and should be regenerated by the normal Convex workflow rather than hand-edited.

## Responsibilities

- Persist product state for users, jobs, applications, milestones, escrows, agreements, submissions, disputes, cancellations, conversations, attachments, reminders, notifications, transactions, reports, waitlist entries, and reputation mirrors.
- Expose typed queries and mutations consumed by the web app through the generated Convex API.
- Run server-side actions that read Soroban contract state through `packages/backend/convex/lib/stellarReads.ts`.
- Maintain guarded admin queries/mutations for metrics, dispute review, notes, and resolution bookkeeping.
- Run deadline reminder scanning on a 15-minute schedule.

## Composition

`packages/backend/convex/schema.ts` composes domain schemas. The main domain folders split schemas, queries, mutations, helpers, and types where the feature is large; smaller domains retain a top-level module such as `jobs.ts`, `escrows.ts`, `disputes.ts`, or `profiles.ts`.

The `packages/convex-client` package re-exports the generated API and exposes browser/server client helpers. It is a typed client boundary, not a chain indexer or a second persistence layer.

## Execution model

- Queries read Convex data and are reactive when used through the client.
- Mutations validate inputs and update Convex state transactionally.
- Actions perform external or asynchronous work, such as RPC reads, then call internal mutations to apply a bounded result.
- `syncMutations.ts` contains the mutation side of chain-state synchronization; it does not independently poll the chain.

## Authorization boundary

Many participant helpers normalize a wallet address and compare it with a stored participant. Several public mutation files still contain TODOs to replace caller-supplied wallet trust with signed wallet-session/auth enforcement. Admin functions have a stronger two-part check: configured admin wallet plus `HIGHRABLE_ADMIN_CONVEX_SECRET`.

See [[backend/Domain Functions]], [[backend/Sync and Scheduled Jobs]], [[architecture/Authentication Boundaries]], and [[data/Convex Schema]].

## Current limits

- There is no general Horizon/Soroban event indexer in the repository.
- Wallet transaction history sync is explicitly post-MVP in `packages/backend/convex/sync.ts`.
- Convex mirrors on-chain escrow/reputation data only when product flows or an explicit sync action invoke them.
- Source-file and attachment content hashing remains incomplete in documented TODO paths.
